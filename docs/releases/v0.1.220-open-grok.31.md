# Open Grok v0.1.220-open-grok.31

This release makes the existing 64-bit Windows distribution a complete,
verified install and update path.

## Windows updates now work

The Open Grok updater now selects `open-grok-windows-x86_64.exe` on 64-bit
Windows, downloads its published SHA-256 file, verifies the binary, runs the
exact-version smoke test, and activates `open-grok.exe` through the existing
locked-file-safe replacement and rollback path.

Previously, Windows releases published an executable but the updater still
reported that no Windows binary existed and rejected the platform before
download. The Windows-only updater suite exposed that mismatch directly.

## Installer and reproducible release build

Windows users can install the latest release from PowerShell:

```powershell
irm https://github.com/mweinbach/open-grok/releases/latest/download/install.ps1 | iex
open-grok --version
```

The installer verifies SHA-256 before replacing the managed command under
`%OPENGROK_HOME%\bin\`. It now rejects unsupported native architectures
clearly instead of requesting an artifact that is not published, and automated
smokes can set `OPEN_GROK_NO_PATH_UPDATE=1` to leave the persistent User
`PATH` unchanged.

The Windows release builder no longer requires a manually installed `protoc`.
It still prefers an explicit `PROTOC` or `protoc.exe` from `PATH`, but can
download the official pinned 29.3 Windows archive, verify its fixed SHA-256,
and cache it under ignored `target/release-tools/`. The release asset set now
also includes the versioned `install.ps1`.

## Windows assets

- `open-grok-windows-x86_64.exe`
- `open-grok-windows-x86_64.exe.sha256`
- `install.ps1`
- `LICENSE`
- `THIRD-PARTY-NOTICES`

Windows binaries are currently unsigned. The checksum and embedded
version/source-commit checks provide release integrity, but there is no
Authenticode publisher identity yet.
