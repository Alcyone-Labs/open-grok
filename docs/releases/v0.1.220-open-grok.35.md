# Open Grok v0.1.220-open-grok.35

This release ports the upstream Grok Build monorepo snapshot `b41c75a`
(SOURCE_REV `91d8cf30`) into Open Grok after the previous sync at `47348d1`.

## Upstream sync (b41c75a)

- **Non-blocking startup** — the leader and stdio agent become ready without
  waiting on `/v1/models` or remote settings. Model catalogs and settings
  refresh in the background after first paint.
- **Fail-closed external OTEL** — customer-owned OTEL stays suppressed until
  settings resolve (pure env API-key leaders without remote fetch can open at
  startup).
- **Bounded session memory** — inherited subagent/fork replay streams updates
  instead of materializing a full typed vector; large session loads get tighter
  peak-memory bounds and soak/testkit coverage.
- **Plan copy with `y`** — from plan approval / plan preview, `y` copies the
  full plan markdown (footer control when width allows).
- **herdr multiplexer detection** — conservative mouse re-encode and doctor
  mapping for the herdr mux; XTVERSION probe skipped under herdr.
- **Source-tagged terminal version telemetry** — env-corroborated
  `term_version` / `term_version_source` on detect and telemetry paths.
- **Auth readiness** — non-interactive path uses bounded refresh without cold
  mint; cold mint moves to post-readiness background work.
- **Settings fetch outcomes** — `Fetched` / `Rejected` / `Retry` with attempt
  budgets and a short startup HTTP client ceiling.
- **Campaign-driven default model** — `/new` re-evaluates an active campaign
  default after boot-time catalog resolution.
- **Embedded boot PTY e2e** — blocked-backend smoke that the UI still comes up
  without hanging (ignored by default).

## Fork invariants kept

- `$OPENGROK_HOME` / `~/.opengrok` / `.opengrok` isolation
- Multi-provider credentials and routing (xAI / Codex / Kimi Platform /
  Kimi Code / Fireworks)
- Remote product feature flags and campaign reseed still dropped at TUI boot
- Open Grok branding and version scheme (not upstream package `0.2.112`)
- Provider export boundary still blocks writeback upgrade when closed
