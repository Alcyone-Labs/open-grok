# Open Grok v0.1.220-open-grok.32

This release brings Kimi Code membership models up to date with the public
Kimi Code catalog, including Kimi K3.

## Kimi Code K3 catalog

Kimi Platform and Kimi Code remain isolated credentials and hosts. The Code
partition now embeds the membership model IDs:

| Model ID | Service | Notes |
| --- | --- | --- |
| `k3` | Kimi Code | Flagship K3, up to 1M context; `low` / `high` / `max` effort |
| `k3-256k` | Kimi Code | Fixed 256K K3 variant; same effort menu |
| `kimi-for-coding` | Kimi Code | K2.7 Code |
| `kimi-for-coding-highspeed` | Kimi Code | K2.7 Code HighSpeed |
| `kimi-k3` | Kimi Platform | Pay-as-you-go Moonshot model (unchanged) |

Code `k3` is not the same slug as Platform `kimi-k3`. Saving a Kimi Code API
key (Settings or `KIMI_CODE_API_KEY`) surfaces the Code catalog, including K3.
Live `/models` discovery is enabled for both Platform and Code when a usable
key is present; failures keep the service-local embedded catalog.

Session rebind after a Platform ↔ Code service switch prefers Code `k3` when
available, then `k3-256k`, then the K2.7 coding family.

## Docs

User guide configuration examples and agent provider notes document the
Platform vs Code model IDs and credentials.

## Windows build fixes

- Leader pipe-name test coverage no longer concatenates `String` with a
  non-`&str` operand, so the shell test crate compiles on MSVC.
- The pager PTY harness only imports the Unix-only
  `process_has_exited_without_reap` helper on Unix, so Windows package builds
  of `xai-grok-pager` succeed again.
